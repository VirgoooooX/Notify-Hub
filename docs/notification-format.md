# 通知格式约定

本约定用于当前 Notify Hub 接入方的消息整理。业务应用负责分类、文案和封面；Notify Hub 负责校验、媒体保存、持久化与渠道投递。

## 默认图文

- 卡片直接交代对象、结果和必要动作，不依赖跳转才能理解。
- 标题标明来源，使用“状态或结论｜具体对象”，避免只写“任务完成”。
- 标题控制在 40 字以内；摘要一至两句，控制在企业微信 news 的 512 字节以内。
- 不发送内部 Prompt、原始浏览器调用日志、带会话参数的地址或敏感凭据。
- 有实际操作入口时可以设置链接；无业务链接时，现有渠道适配器使用封面地址作为点击目标。news 卡片不支持点击展开完整正文。

## 封面

统一使用横向 1068 × 455 布局：左半边居中放主应用 Logo，中间竖线分隔，右半边为两行分类文字和小图标。右侧文字块与小图标高度接近、按中心对齐。主 Logo 保留充分留白，不占满左半边。

每个类别使用自己的浅色背景、同色系深色文字，不统一套一个底色：

| 来源与类别 | 背景 | 右侧图标 |
| --- | --- | --- |
| Fleetge · 容器更新 | 青灰 | 该 Stack 的一个代表图标 |
| Fleetge · 到期提醒 | 暖金 | 该 Host 的 Logo，未配置时用通用主机图标 |
| Fleetge · 流量预警 | 淡紫 | 该 Host 的 Logo，未配置时用通用主机图标 |
| Browser Publisher · 登录维护 | 浅蓝 | 登录图形 |
| Browser Publisher · 发布异常 | 浅红 | 异常图形 |
| Browser Publisher · 发布确认 | 浅绿 | 确认图形 |
| Hermes · 任务结果 | 淡粉紫 | 任务清单图形 |
| Notify Hub · 监控告警 | 浅杏 | 健康监测图形 |
| Notify Hub · 监控恢复 | 薄荷绿 | 恢复图形 |

Browser Publisher 使用第一版“浏览器窗口、纸张与发布箭头”图标，不使用 BP 字标。Fleetge 更新通知只使用 Stack 图标，不拼接 Compose 中各容器的图标；到期及流量通知在首次发送前读取 Fleetge 的 Host Logo 配置，复用其内置品牌或自定义图片，不另建 Logo 配置。已生成消息的封面随消息冻结，后续 Logo 修改用于新的通知。

## 例外与交互

- 登录二维码：发送二维码原图与简短文字，不用分类封面替代或缩小二维码。
- 待办及催办：保留每条提醒的自定义封面、图文内容及现有交互配置；图文和可交互可以同时存在。
- 操作回执：保留简短文字。
- Hermes 明确要求发送的长正文：保留完整文字，避免图文摘要截断；短消息默认使用任务结果卡片。
- 现有 Codex、Romano 资讯图文继续由所属插件维护，本轮没有修改它们的业务判断及文章生成。

## 投递与失败

外部应用通过现有媒体 API 上传封面，再通过事件 API 提交消息，需要给相应客户端开启媒体权限。网络请求不得进入数据库事务。保持原事件键、接收人、限流、重试与恢复语义，不因展示调整重发历史消息。

Stack 图标不可用时使用通用分类封面；封面上传失败时仍提交文字结果。API 返回 202 只表示 Notify Hub 已持久接管，不表示微信已送达。上线后还需在实际接收端检查封面裁切及标题、摘要展示。
